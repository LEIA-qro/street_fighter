🎯 Mission & Core Objectives

This project implements a production-grade RL pipeline for Street Fighter II' - Special Champion Edition (USA) on the Sega Genesis. A PPO agent (via Stable Baselines3) is trained to play as Ryu using a manual, developer-controlled curriculum against increasingly difficult opponents.

Core Innovation: A custom, lock-step TCP bridge between Python and BizHawk (Lua). This replaces gym-retro, providing absolute control over frame skipping, save states, reward shaping, and curriculum phases.

Primary Goals:
 1. Train a Ryu specialist capable of defeating all 12 opponents on the hardest difficulty.
 2. Maintain a strict multi-algorithm architecture (e.g., seamless swapping between PPO, SAC, DQN).
 3. Ensure a reproducible, crash-resilient training loop with automatic checkpoint recovery and Optuna hyperparameter optimization.

🏛 Architectural Mandates

1. Directory Structure Adherence
 * street_fighter/ must remain inside BizHawk-2.8-win-x64/.
 * roms/: Read-only. Never modify.
 * states/: BizHawk .State files.
 * lua/v2.0/: Contains headless (training_env_client.lua) and interactive (match_test_env_client.lua) loops.
 * lua/generated_config.lua: Auto-generated by Python. Do not edit manually.
 * src/: Python source. Strictly isolated into core/, envs/, agents/, and scripts/.

2. Strict Layer Isolation
 * core/ handles the emulator lifecycle and TCP bridging. It must have zero knowledge of RL algorithms.
 * envs/ defines the Gymnasium interface. It must have zero knowledge of training loops.
 * agents/{algo}/ implements the training logic. Never import from a sibling algorithm directory.
 * scripts/ are thin CLI wrappers. They contain no business logic.

3. Plugin Architecture via Composition
 * All agents must implement the BaseAgent ABC methods: train, resume, tune, test.
 * Scripts dispatch algorithms dynamically via importlib. Adding a new algorithm (e.g., SAC) must require zero changes to core/ or envs/.

4. Lock-Step TCP Protocol
 * Communication is strictly one-send/one-receive per step.
 * The Lua script acts as a spinlock, blocking until Python responds.
 * Python's TCP reads must use a \n-delimited stream buffer to handle partial reads safely.
 * Format: Commands sent as "{len} {payload}\n".

5. State Management & Curriculum
 * Observations: 2216-dimensional float32 vector (554 dims/frame × 4 stacked frames). Layout includes positions, velocities, and one-hot encoded actions/characters.
 * Phase Changes: config.TRAINING_STATES is static after spawning SubprocVecEnv. Phase changes must be broadcast exclusively via env.env_method("set_training_states", new_states).
 * Manual Promotion: The curriculum is manual via callback.set_phase(n). The callback triggers saves upon hitting WIN_RATE_THRESHOLD (75%) but does not auto-advance to prevent promotion due to statistical noise.

🎨 Coding Standards

 * Style: Strict PEP 8. Max line length 100.
 * Typing: Use explicit type hints on all function signatures in src/.
 * Naming: PascalCase for classes. snake_case for variables/functions. UPPER_SNAKE_CASE for constants. _leading_underscore for private internals.
 * Data Types: All observations must be dtype=np.float32. SB3's MlpPolicy will fail on int32.
 * Reward Safety: Clamp all raw RAM deltas before use (current threshold: 100 HP units) to prevent RAM glitches from corrupting the value function.
 * Error Handling: No bare except: clauses. Catch specific exceptions. Log and re-raise in training mode; log and recover in interactive mode.

⚠️ Critical Constraints & Safety Rules

 1. ROM Integrity: Never modify files in roms/.
 2. Git Exclusions: Ensure .State files and generated_config.lua remain in .gitignore. They contain binary data and machine-specific absolute paths.
 3. Model Resumption Safety: Never change N_STEPS or BATCH_SIZE when resuming an existing model. These structurally define the rollout buffer. Changing them discards all learned weights.
 4. Zombie Process Prevention: You must invoke failsafe_env() within the finally block of every training/execution script. This is required to kill orphaned EmuHawk.exe processes, terminate subprocesses, and purge CUDA VRAM. Failure to do so will leak ports and crash the GPU.
